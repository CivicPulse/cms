<task type="auto">
  <name>Task 2: Create src/env.ts — Zod startup validation</name>
  <files>src/env.ts</files>
  <action>
    Create `src/env.ts` with the following exact content:

    ```typescript
    import { z } from 'zod'

    export const env = z
      .object({
        PAYLOAD_SECRET: z
          .string()
          .min(32, 'PAYLOAD_SECRET must be at least 32 characters'),
        DATABASE_URL: z
          .string()
          .min(1, 'DATABASE_URL is required — set it in .env.local'),
      })
      .parse(process.env)
    ```

    This module throws a `ZodError` at import time if either variable is missing or invalid. Next.js surfaces this as a clear startup error with field-level messages. Do NOT wrap with try/catch — the throw is intentional.

    The `|| ''` fallback in `src/payload.config.ts` is removed in plan 01-02, not here. This plan only creates the validation module.
  </action>
  <verify>
    <automated>test -f src/env.ts && grep -q "PAYLOAD_SECRET" src/env.ts && grep -q "DATABASE_URL" src/env.ts && grep -q "min(32" src/env.ts && echo "src/env.ts present with correct validations"</automated>
  </verify>
  <done>
    - `src/env.ts` exists
    - Exports `env` object using `z.object({ PAYLOAD_SECRET: z.string().min(32, ...), DATABASE_URL: z.string().min(1, ...) }).parse(process.env)`
    - No try/catch wrapping — ZodError propagates at module load time
  </done>
</task>

<task type="auto">
  <name>Task 3: Docker Compose + .env.example update</name>
  <files>docker-compose.yml, .env.example</files>
  <action>
    Create `docker-compose.yml` at the repo root with the following content:

    ```yaml
    version: '3.9'

    services:
      postgres:
        image: postgres:16-alpine
        environment:
          POSTGRES_DB: civpulse_cms
          POSTGRES_USER: payload
          POSTGRES_PASSWORD: localdev
        ports:
          - '5432:5432'
        volumes:
          - postgres_data:/var/lib/postgresql/data
        healthcheck:
          test: ['CMD-SHELL', 'pg_isready -U payload -d civpulse_cms']
          interval: 10s
          timeout: 5s
          retries: 5

    volumes:
      postgres_data:
    ```

    Overwrite `.env.example` with the following content (the file currently only has `PAYLOAD_SECRET=your-secret-here`):

    ```
    # Required: Postgres connection string
    # Local dev: use Docker Compose values below
    DATABASE_URL=postgresql://payload:localdev@localhost:5432/civpulse_cms
    ```

    Do NOT create `.env.local` — that is a developer's responsibility and is gitignored.
