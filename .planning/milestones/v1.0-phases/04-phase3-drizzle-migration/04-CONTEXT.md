## Implementation Decisions

### Migration workflow (carried from Phase 1)
- Migration files committed to git under `src/migrations/`
- Generated via `npx payload migrate:create`
- Verified via `npx payload migrate`
- Production entrypoint: `payload migrate && next start` (auto-migrate on startup)
- `push: process.env.NODE_ENV === 'development'` — dev auto-pushes, prod requires migrations

### Schema changes to capture
- Posts: `versions: { drafts: true }` — creates `_posts_v` version table + `_status` column
- Posts: `featuredImage` upload relationship field — new column on `posts`
- SiteSettings: `navItems` repeating array — creates `site_settings_nav_items` table

### Claude's Discretion
- Migration file naming (timestamp-based, auto-generated by Payload)
- Verification approach (manual or scripted)
