  <name>Task 2: Webhook hook + email-status context fix</name>
  <files>src/hooks/fireWebhook.ts, src/app/(payload)/api/posts/[id]/email-status/route.ts, src/collections/Posts.ts</files>
  <action>
  1. **Create src/hooks/fireWebhook.ts:**
     - Export `firePostPublishedWebhook` as a `CollectionAfterChangeHook` from `payload`.
     - Guard conditions (return `doc` early if any fail):
       a. `if (context.skipWebhook) return doc` -- prevents infinite loop from email-status callback
       b. Only fire on publish transitions: `previousDoc?._status !== 'published' && doc._status === 'published'`. On `create` operation where `doc._status === 'published'`, also fire (direct publish without draft).
       c. Only fire when `doc.publishAs === 'email' || doc.publishAs === 'both'`
     - Extract tenantId: `const tenantId = typeof doc.tenant === 'object' ? doc.tenant.id : doc.tenant`
     - Build JSON payload: `{ postId: doc.id, tenantId, publishAs: doc.publishAs }`
     - Compute HMAC-SHA256 signature using `crypto.createHmac('sha256', process.env.WEBHOOK_SECRET!)` over the JSON payload string
     - Fire-and-forget fetch POST to `process.env.RUN_API_WEBHOOK_URL!` with headers `Content-Type: application/json` and `x-webhook-signature: {signature}`. Use `.catch()` to log errors via `req.payload.logger.error()` without blocking the response.
     - Return `doc`.
     - Use `process.env.*` directly (not env.ts import) since hooks run in Payload context where env.ts may not be the first import.

  2. **Update email-status route (src/app/(payload)/api/posts/[id]/email-status/route.ts):**

     - No other changes to the route.
